# School-linked daily worksheets

Turn a child's **actual school timetable** into a daily practice sheet: the subjects he sat
through today (or has tomorrow) become the subjects on his worksheet, generated by the same
engine that powers kids-education.trigunai.com.

```bash
python3 kids_quiz/school/daily_worksheet.py                    # today
python3 kids_quiz/school/daily_worksheet.py --tomorrow --n 5   # tonight, for tomorrow
python3 kids_quiz/school/daily_worksheet.py --date 2026-08-21
```

Output in `out/`: a print-ready **PDF**, the items as **JSON**, and an on-screen **link per
subject** into the live kids app (read-aloud + adaptive).

## Why there is no portal scraper

The school portal (`cags.edusprint.in`) puts an **image CAPTCHA** on every login —
`POST /cags/Security/Login/MCampusLogin` requires `SiteUserName`, `SitePassword` **and**
`LoginCaptcha`, with the image served fresh from `/cags/Uploader/Captcha`. Sessions also
expire quickly (an unauthenticated request is bounced with `Authentication Session Expired`)
and the session cookie is `HttpOnly`. So there is no unattended login to build, by design of
the site — and solving CAPTCHAs isn't on the table.

It isn't needed. **A timetable is a fixed weekly grid**, not live data. Capture it once into
`<profile>.json`, and everything that genuinely varies day to day — which weekday it is,
which periods run — is computed locally, offline, forever.

## Files

| File | What it is |
|---|---|
| `timetable.py` | Loads a profile, maps school period names → engine subjects, answers "what should he practise on this date" |
| `shivaay.json` | The child's profile + the full Mon–Fri grid, captured from the portal 2026-08-18 (Sat/Sun are genuinely empty — the school marks every Saturday WEEKEND) |
| `daily_worksheet.py` | Generates the day's questions, renders the PDF, prints the app links |
| `com.trigunai.kidsdaily.plist` | launchd job — nightly at 19:30 for the next day (load it once the timetable is real) |

## Subject mapping

`SUBJECT_MAP` in `timetable.py` translates III-A's real period names to the subjects the
engine serves. Anything with no bank maps to `None` and is **reported as skipped**, never
silently swapped for something else. A name that isn't in the map at all is reported as
**UNRECOGNISED**, so a new subject on the timetable gets noticed instead of vanishing.

| School period | → | Why |
|---|---|---|
| Mathematics, Mathlab | Mathematics | computed, unlimited |
| English | English | |
| Hindi | Hindi | |
| Science, Science Activity, Social Studies | EVS | ICSE splits at class 3 what our EVS bank covers together |
| Marathi | *skipped* | no Marathi bank |
| Robotics and Computers | *skipped* | no computing bank |
| Financial Literacy | *skipped* | no bank |
| Assembly, Value Education, Athletics, Traditional Game, JPETT, Craft, Drawing | *skipped* | not practice subjects |

**Period count weights the sheet.** Three English periods and one Maths period is a day that
leaned on English, so English gets more questions: `n + (periods - 1)`, capped at `2n`.

To add a school subject, add one line to `SUBJECT_MAP`.

## The week as it currently runs

| Day | Practice generated | Skipped |
|---|---|---|
| Mon | Maths, EVS×2, Hindi×2 | Athletics×2, Financial Literacy, Traditional Game |

| Wed | English×3, EVS×2, Maths×2 | JPETT |
| Thu | English×2, EVS×2, Maths×2 | Robotics×2, Craft, Drawing |

## Rendering

The PDF is produced by the **app's own print renderer**
(`lms/app/static/kids/worksheet_print.js`), so paper matches the product exactly — one
renderer, not two to keep in sync. It's served over a throwaway `127.0.0.1` server for the
duration of the print because `assets.js` *fetches* the art manifest, and `fetch()` is blocked
on `file://` — printing straight off disk silently degrades picture questions to bare words
("rabbit rabbit rabbit" instead of five rabbits).

## Known gaps

- **Hindi sheets carry English instruction lines** ("Circle the one that does not belong").
  The on-screen app localises these per item; `worksheet_print.js` does not. Fixing it touches
  the shared renderer, so it needs a kids-app deploy alongside.
- **Board is inferred, not confirmed** — `shivaay.json` says ICSE because the timetable lists
  Science and Social Studies as separate class-3 subjects plus Marathi as a language, which is
  the ICSE pattern (CBSE class 3 teaches one combined EVS). It picks the question bank. If it's
  the CBSE branch, change one word — that bank exists too.
- **No Marathi, computing or financial-literacy content**, so those periods produce nothing.
  Tuesday's only "extra" academic period is Marathi, so Tuesday's sheet is Hindi + English + EVS.
