# Acharya University — "University in a Box" (self-taught learning OS)

> Revamp of the single-subject Acharya tutor into a **multi-agent, learn-ANYTHING
> university** where the *subject/curriculum itself is generated by AI* as a
> first-class component. Built fresh and self-contained so it does **not** touch the
> live WhatsApp/Gurukul student flow (standing rule: don't disrupt live students).
> First user = Deepak, on web, for his own learning.

Framework = **ALTER** (from the "university in a box" idea):
**A**dvisor · **L**ibrarian · **T**utor · **E**ditor · **R**oommate — orchestrated by a
**Registrar**, over one authoritative **Learner Model** and a per-goal **Curriculum**
that AI writes on demand.

---

## 0. Why revamp (what the old tutor gets wrong)

The old Acharya is really only the **T** in ALTER, and only over *pre-loaded* subjects:
- One monolithic system prompt executed as one session per student.
- Curriculum is hand-authored JSON (`courses/*.json`) → can't "learn anything."
- Learner state is a flat JSON preamble re-injected every turn; no orchestrator, no
  cross-agent state bus.
- No Advisor (no goal→syllabus), no Librarian (no sources), no Editor (no feedback on
  your real output), no Roommate (no range).

Target: type **any** goal → AI builds your personal degree → 5 specialised agents run it.

## 1. Target architecture (the whole system)

```
  learner turn ─► REGISTRAR (router: intent + journey-phase → agent)
                        │  reads/writes
        ┌───────────────▼────────────────┐
        │      LEARNER MODEL (source of   │
        │   truth): goals, curriculum,    │
        │   mastery, misconceptions, SRS, │
        │   shelf, milestones             │
        └──┬─────┬─────┬─────┬─────┬──────┘
      ADVISOR  LIBRARIAN TUTOR EDITOR ROOMMATE
        (A)      (L)     (T)   (E)     (R)
                  │ builds/queries
             SOURCE SHELF (per-curriculum RAG)
```

### The six roles

| Role | Job | Trigger | Reads → Writes |
|---|---|---|---|
| **Registrar** | route each turn to the right agent | every turn | learner state → agent choice |
| **Advisor (A)** | interview → **generate the curriculum** (destination, baseline, sequence, cut-list, milestones) for ANY goal | new goal / drift | goal → `curriculum` + `milestones` |
| **Librarian (L)** | curate 3–5 trustworthy sources per unit; triage signal/noise; build the shelf (RAG) | Advisor finishes a unit / "what do I read?" | unit → `shelf[unit]` |
| **Tutor (T)** | 1:1 Socratic — open a gap, retrieve-don't-explain, catch confident-wrong | default in a study session | mastery+shelf → mastery deltas, misconceptions, SRS |
| **Editor (E)** | grade the learner's **produced work** vs the milestone; challenge logic, tighten | milestone deliverable submitted | rubric → milestone pass/fail (unblocks next unit) |
| **Roommate (R)** | cross-domain perspective / range; connect topic to a different field | session end / idle / boredom | — → interest + retention hooks |

### The two things that don't exist today (the real build)
1. **Registrar** — a thin classifier `(intent, journey_phase, learner_state) → agent`.
2. **Unified Learner Model** carrying a first-class **`curriculum`** object (units,
   sequence, cut-list, milestones, shelf, mastery). Safety rule kept: **only code grants
   `solid` mastery, never the model.**

## 2. Data model (Learner Model v2)

JSON on disk in Phase 1 (single-user, local), Postgres later (multi-user).

```jsonc
// learners/<user_id>.json
{ "user_id", "name", "created_at", "goals": ["<curriculum_id>", ...] }

// curricula/<curriculum_id>.json   ← the AI-generated "subject"
{
  "curriculum_id", "user_id", "title", "goal",
  "destination",   // what you can DO at the end
  "baseline",      // where you start
  "why",           // motivation hook
  "cut_list": ["things to ignore for now", ...],
  "status": "active|done",
  "created_at",
  "units": [
    {
      "unit_id", "title", "summary",
      "objectives": ["...", ...],
      "concepts": [ {"key","name","recall","answer","mastery":0.0} ],
      "sources":  [ {"type":"video|article|book|paper","title","url","note"} ], // Librarian
      "milestone": { "prompt": "...", "rubric": ["...", ...] },                 // Editor
      "mastery": 0.0,
      "status": "locked|active|done"
    }
  ]
}

// sessions/<curriculum_id>__<unit_id>.json   ← tutor conversation state
{ "history": [{"role","content"}], "updated_at" }
```

Mastery ladder (kept from old system): `0.0 weak · 0.5 shaky · 1.0 solid`.
Model may only mark `shaky`; `solid` is granted by deterministic recall grading (code).

## 3. Phased build plan

Each phase ships something usable. ✅ = done, ▶ = in progress, ☐ = todo.

### Phase 1 — Vertical slice: "type a goal → get a degree → learn a unit"  ✅ BUILT
The proof that the **subject is AI-generated**. Self-contained web app, run locally.
- ✅ `llm.py` — Azure/OpenAI-compatible chat helper (reuses AOAI_* env, like `lms/app/tutor.py`)
- ✅ `store.py` — JSON learner-model store (learners / curricula / sessions), atomic writes
- ✅ `agents/advisor.py` — interview (≤5 questions, one at a time) → generate curriculum
- ✅ `agents/tutor.py` — Socratic per-unit tutor + recall grading (code owns `solid`)
- ✅ `server.py` — FastAPI: advisor interview/build, curriculum read, tutor step, recall/mastery
- ✅ `web/index.html` — single-page UI (new goal → interview → syllabus → unit tutor → recall)
- **Done when:** Deepak types "learn business finance", gets a curriculum, opens unit 1,
  the Tutor teaches it, recall turns concepts green + unlocks the next unit. ✅ wired.
- **To run:** `pip install -r requirements.txt`, export `AOAI_*`, `uvicorn server:app --port 8010`.

### Phase 2 — Registrar + Learner Model v2 hardening  ☐
- Real orchestrator: `(intent, phase) → agent`. Replaces UI-driven routing.
- Mastery engine: recall grading grants `solid`; SRS boxes `1→3→7→16→30`.
- Journey state machine per unit: `intro → teach → check → milestone → done`.

### Phase 3 — Librarian + Source Shelf (grounding)  ☐
- Per-unit source curation (web search + your existing qbank/RAG muscle).
- Store shelf refs + embeddings; Tutor/Editor cite the shelf (anti-hallucination).
- NotebookLM-style "make this a briefing/podcast" is optional stretch.

### Phase 4 — Editor + Roommate  ☐
- Editor: submit a deliverable → graded vs milestone rubric → unblock next unit
  (generalise `teachback_grade()`).
- Roommate: cross-domain prompts at session end (promote old "IMAGINATION MODE").

### Phase 5 — Multi-user + persistence + deploy  ☐
- Move JSON → Postgres; add auth (reuse Acharya session cookie).
- Deploy as its own Azure Container App / route (isolated from live Acharya).
- Optional: wire the WhatsApp bridge to this brain once proven on web.

### Phase 6 — Flywheel  ☐
- LearningEvent logging → knowledge-tracing model → the Advisor sequences better over
  time (feeds `tutor_rl/`). This is the moat.

## 4. Tech + conventions
- **Backend:** Python + FastAPI (matches `lms/`). LLM via Azure OpenAI (`AOAI_*` env) or
  any OpenAI-compatible base URL (e.g. the litellm proxy). See `llm.py`.
- **Frontend:** single static `web/index.html` (no build step) — fast to iterate, easy to
  fold into the Acharya frontend later. LaTeX via `$...$` (KaTeX) like the exam tutor.
- **Storage:** `data/` JSON (gitignored). Postgres in Phase 5.
- **Isolation:** nothing here imports or writes the live `~/.openclaw/students/*` or the
  LMS Postgres. Separate process, separate data dir.

## 5. Run (Phase 1)
```bash
cd acharya_university
pip install -r requirements.txt
export AOAI_ENDPOINT=... AOAI_KEY=... AOAI_DEPLOYMENT=gpt-4o-mini   # or OPENAI_* (see README)
uvicorn server:app --reload --port 8010
# open http://localhost:8010
```
